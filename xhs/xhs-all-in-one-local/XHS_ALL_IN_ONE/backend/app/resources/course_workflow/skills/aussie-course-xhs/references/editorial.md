# 从学生问题决定内容，而不是从模板填空

已确认参考稿约束视觉身份与资料真实性，不锁定叙述。每篇要让学生获得一个可以使用的新判断；课程名称、产品目录和截图数量本身不足以构成这个收获。

## 做稿前的编辑判断

在内部简要记录以下内容，不把它变成用户必须填写的新问卷：

- **具体问题与依据**：学生在哪一步会卡住？依据是真实提问、用户反馈，还是教材与讲义支持的教学推断？缺少站内需求数据时明确待测。
- **读完能做什么**：用一句可观察的行为描述收获，例如能辨认配对设计、解释估值归属，避免“全面掌握、提升认知”。
- **本篇增加什么**：一个解释、数据关系、反例、判断条件或讲义使用示范。即使不购买资料，读者仍应得到完整的学习帮助。
- **资料怎样接住问题**：哪些真实样张支持这个收获？样张具体能让学生继续练什么？选出证据再决定展示数量，不用无关章节补齐图库。
- **为什么这样讲**：让知识的关系决定叙述与图形。必要时比较少量真正不同的角度，直接选择证据与读者收获最匹配的一个；无需每篇向用户提交三套标题。

## 用内容选择表达方式

图形变化适合逐步画图或反例；方法选择适合把数据关系、条件和判断连起来；计算链适合有单位的过程表；资料选购疑问适合批注真实样张。这里是可选例子，不是分学科固定模板，也不是轮换表。

自测、错误与正确写法、课程简介、知识清单、公式放大都可用，但只有它能推动当篇解释时才出现。不要求每篇都先自测、都列三条、都讲全课概况、都展示同样数量的完整样张。题目也不必全错；自测须有辨别价值。

保留白底、蓝橙、学校文字与课程代码、真实品牌页脚、多张真实缩略图和完整样张。布局可按内容变化：图形可以承担主视觉，计算过程可做表，数据可用小图解释。不要用换配色、随机重排或加插画冒充选题差异。具体尺寸按完整样张比例与可读性适配。

## 改稿时看近期真实成稿

优先比较同账号、相近用途的近期稿；若没有，说明没有比较对象。检查它们的开头、段落形状、知识组织、视觉关系、样张用途和结尾是否重复。同一句开场跨课程复用、每篇都先列三个错误、截图换了但解释不变，是需要重做编辑判断的信号；统一品牌页脚不算问题。

如果去掉学校和课程代码后，两篇仍可互换大部分内容，回到具体例子、条件和资料证据重写。共同的必要定义可以保留，避免为了差异牺牲正确性。不设置机械的相似度阈值，也不要求每篇故意与上一篇相反。

## 真实试稿与反馈

技能改动用实际成稿验证：保留旧稿，提供新稿、来源映射和改动理由。尺寸、完整性、公式、版本等可客观核验；“更想点开、更有用”需要用户或实际读者反馈，不能由模型分数代替。自编试稿不称独立盲测，GitHub方法不证明小红书流量提升。

用户反馈优先修正产生问题的判断，避免再加一条所有课程必须执行的栏目。只有用户明确要求保存的长期偏好才写回技能。
