# 学生需求与选题

## 从具体阻塞点开始

| 学习阶段 | 要验证的问题 | 可以交付的内容 |
|---|---|---|
| 开学/预习 | 不清楚概念关系、术语、先修知识 | 概念图、中英术语、先修自查 |
| 跟课 | Lecture理解了却不会做Tutorial | 读题方法、选择方法的条件、步骤示范 |
| 期中/期末 | 范围多、练习乱、时间不足 | 范围核对方法、复习顺序、错题分类 |
| 模拟训练 | 不会分配时间、看解析像懂了 | 自编练习、独立作答检查、复盘方法 |
| Assignment | 看不懂任务动词和Rubric | 要求拆解、评分标准理解、结构判断 |
| 资料选择 | 不知道学期/范围/题量是否匹配 | 真正样页、目录、适合/不适合谁 |

这是待验证的内容方向，不宣称该学生或课程必然有这些问题。

## 研究口径

- 首先查用户已有资料和账号记录；真实提问可优先使用，公开展示须去身份。
- 对标先看同校同课，再看相近学科方法；不能把留学申请、K12英语或生活类账号的表现直接迁移到课程资料。
- 采样包含普通和较高互动内容，记录发布距今时长；避免只挑爆文，不从单条爆文推断因果。
- 保留来源、采样时间、大学/课程（若确证）、学生问题、内容类型、可见赞/藏/评、未知字段与观察结论。
- 用户要求“拿到真实数据前不要制作”时，将其作为本轮条件；不足时只交研究状态、缺口与候选问题。普通无此要求的任务可基于已知事实做待测草稿。
- 搜索未完整覆盖小红书时写“公开索引线索”，不能据此宣布站内热度排行。

## 候选卡与标题

每个候选讲清：谁、在哪个阶段、卡什么、解决到哪一步、证据在哪里、为何适合本账号。按需求具体度、真实价值、证据完整性、时点与成本排序；内部编辑分值不能冒充平台预测。

制作前比较少量有差别的角度，并记录：学生为什么愿意点开、读完有什么完整收获、哪部分值得回看/收藏、选定产品能否用真实样页兑现。点开、收藏和资料咨询只是不同编辑目标，不能写成平台算法权重或保证效果。

“课程介绍”“重难点”“产品简介”是内容材料，不自动构成好选题。把它们组织在具体问题下：例如“换个情境就不会画供需图”对应读题与判断条件；“解析看懂却独立做不出”对应遮住解析后的迁移检查。保留课程本身的重要性，但不要用学生视角包装空泛广告。

标题从真实问题和完整收获提炼，不维护可直接替换代码的固定标题池。问题、方法、反例、讲义批注均是可选切入点。

课程代码仅在已知归属且确实讲该课时加入；通用方法不强贴代码，不堆无关学校标签。

## 目标与复盘

每次改稿先记录用户原话、已确认要求和这篇仍待验证的选择，区分选题、文字、样页与设计反馈。用户要求打磨本技能时，把明确共性要求写回对应参考；不要把未经反馈的本轮标题、页数或字号固化为标准。用户未要求自动监测时，不创建定时任务。

把被看到、觉得有用、进一步了解资料分开观察。自有后台有曝光/阅读时才算相应比例；竞品没有分母时只报告可见互动，不写互动率。固定可比较的观察窗口，例如发布后48小时与7天（仅试验设置），对比同目的内容。

自然流量前后变化不能称为随机实验因果。资料、试读或价格的真实询问与泛泛点赞分开。公开昵称/主页仅是需求研究线索，不承诺可导入广告系统逐人定向。

## 先检查新增价值

区分真实学生原话与教学推断；没有真实提问记录时不写“学生都在问”。选题至少有一个由内容支持的新判断、具体例子或资料使用示范。抽象栏目名和产品名称不足以成为选题。如何选择叙述与比较近期稿，见 [内容编辑判断](editorial.md)。
